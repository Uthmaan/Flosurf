Design System Architecture & Principles

          

            A strict 3-tier token topology combined with an automated 4-stage architectural gate.
          


          
1. Strict 3-Tier W3C Token Topology

          

            To ensure scalability across web and mobile platforms, tokens are strictly separated into three isolated tiers:
          

          
    
            
  • Tier 1 (Primitives): Raw, context-agnostic scales (e.g. palette.nimbus.n50). Rule: Never reference directly in application code.
    • 
            
  • Tier 2 (Semantic): Context-aware aliases that switch across Day, Night, Day-HC, and Night-HC.
    • 
            
  • Tier 3 (Component): Scoped component primitives (e.g. button.primary.bg.default) enforcing WAI-ARIA and state matrices.
    • 
          


          
2. Pre-Handoff 4-Stage Architectural Gate

          

            Prior to shipping code to production repositories, the automated CI pipeline enforces:
          

          
    
            
  • Gate 1 (Zero Hardcoded Hex/Px): No raw hex codes or pixel bounds can bypass design tokens.
    • 
            
  • Gate 2 (WCAG 2.2 AA Contrast): Minimum 4.5:1 for body copy and 3:1 for UI boundaries across all 4 modes.
    • 
            
  • Gate 3 (State Matrix Contract): All interactive components must implement 6 states (`default`, `hover`, `focus-visible`, `active`, `disabled`, `loading`).
    • 
            
  • Gate 4 (Layout & Stress Test): Resilient to 300% browser text magnification and nominal compounding across South African language families.
    •
